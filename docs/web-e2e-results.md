## Defects fixed

- A work stop request initially received HTTP 400 because the task ID was encoded as a JSON string. The request now validates the decimal ID and emits the digits as an unquoted JSON number, preserving the exact value without JavaScript numeric rounding. The follow-up network capture returned HTTP 200 and the exact wire ID matched the selected task. Server readback ended in `completed`, not `cancelled`.
- The task-tree reader now includes asynchronous handoffs saved in the local recovery receipt, so recovery does not depend only on task cards still present in the main conversation response. A stop request no longer changes a completed Web run to cancelled merely because the request was accepted.
- After `Input.insertText`, a live Work composer briefly still reported an empty draft before painting the exact text. The old guard failed safely before Send. The fix polls while the editor is temporarily unavailable or the draft is empty, keeping the pinned identity, route, mode, attachment and generation checks active; a nonempty mismatch still fails, and neither text insertion nor Send is retried. The resulting fresh Work lifecycle passed.
- A separate ordinary-chat route transition exposed a post-ACK error: the server accepted the create and returned IDs while the browser briefly used `/chat/local_<16 digits>` before navigating to `/chat/<numeric-id>`. The old numeric-only route check reported an error after acceptance. IDs remained intact, and wait on that same run recovered successfully. The fix permits only this exact same-origin local-ID transition after a matching native ACK; initial target, origin, and account guards remain strict. This is distinct from the pre-Send empty-draft rejection above.
- Submission handling focuses the intended visible editor, waits for hydration and a ready Send control, and checkpoints accepted IDs immediately on the matching native ACK. It then waits for the accepted conversation route before returning success. Control-card state is preserved in reads. Account identity checks run before and after the guarded operation in the same evaluation, so a mid-run account switch fails while retaining already known recovery IDs. The native API-parameter poll is capped at three seconds and bounded by the caller's remaining time.
- Web async recovery initially used the desktop API5 origin and reported `Failed to fetch`. The verified same-origin `/chat/async/chunk_stream` endpoint returned HTTP 200 and SSE events for the same accepted task. The adapter now uses that origin; real checkpoint recovery passed without a new send.
- Quiet stream reads and JSON requests now share an absolute deadline, including delayed evaluation and cancellation. Hung fetch/read/body/cancel cannot indefinitely hold the observation; expired operations cannot start another request or advance a saved checkpoint. Browser observations preserve the CDP connection. Stop retains known IDs and `stopped:false` when state cannot be confirmed, and identity changes still fail with the known result.
- A short external initialization delay was observed. Once IDs were available, the run could be queried later without resubmitting the message.
- Fresh login startup briefly reported the requested Doubao target URL while its renderer remained `about:blank`, producing an origin error. Login now waits through that exact initial blank state within its deadline; an external origin still fails. The historical failed launch is retained separately, and the successful retest asserts `login_timeout` explicitly rather than counting any nonzero exit as a pass.

## Remaining limits

- The two accounts were not each tested in both chat and Work modes.
- Live Work stop did not prove that any child node reached `cancelled`; the demonstrated result was a completed server tree. Keep this distinct from the confirmed ordinary-chat cancellation case.
- The package installer upgrade branch remains unverified because update check reported the installed version as current.
- New manual sign-in with real credentials or verification codes was not exercised; the logged-out-to-signed-in transition is covered by a controlled test.
